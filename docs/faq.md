# 排错

## 装完重启了，模式选择器里没有「智能开发模式」

先确认 `dsh-preset-smart-dev` 真的装上了。在 DSH 插件页看它是否在已安装列表里，状态是启用。

如果包在、模式不在，多半是组合时这一层 patch 被拒了。检查两处：

1. **面板没装**。预设里引用了 `dsh-smart-dev-panel/superagent-router`，面板缺失会让整条预设组合失败。先把面板装上再重启。
2. **profile 里已经有同 id 的预设声明**。比如之前手工把 `preset-smart-dev` 写进过 `cordis.patch.yml`，现在又装了包，两处 id 重复。删掉 profile 里手工那段。

## 右侧栏没有「智能开发」面板

面板是 Web client，只在 Web / 桌面端出现，且要 `dsh-smart-dev-panel` 这个 bundle 被选中。装包不等于选中：装完在插件页确认它处于启用状态。

如果面板在别的会话里出现、唯独 `smart-dev` 会话没有，那是预期行为之外的——面板本应随 `smart-dev` 会话自动打开，报个 issue 带上会话截图。

## 面板在，但工单通道报不可用

工单通道需要 `dsh-preset-superagent-local`。它是可选的，没装时桥接入口仍然存在但无处投递，面板里对应分区会显示不可用。

装好它之后还需要：

- 工作区是一个 Git 仓库，且有至少一个提交（工单以 HEAD 为基线）；
- 环境里有可执行的 `git`；
- 已配置模型。

缺任意一项时，智能开发模式会在原会话里直接回答或讨论方案，不会强行建单。

## 索引加进去了，发现页还是空的

DSH 的插件市场默认不启用。随附的 profile 里没有挂 `plugin-market` 服务，需要先在插件页启用对应的组合包，再回设置里添加索引地址。

另外索引地址必须是公开可访问的 `https`，且能被直接 GET 到 JSON。指向私有仓库的地址取不到。

## 装的时候报版本不兼容

三个包都声明了 `engines.dsh`：`>=0.2.0-0`。DSH 低于这个版本时市场会标成不兼容，装也会被拒。

注意预发布版本：`0.2.0-rc.1` 这类带后缀的版本需要范围里含预发布标记才匹配，所以这里写的是 `>=0.2.0-0` 而不是 `>=0.2.0`。

## 更新到新版本怎么操作

索引里每个版本固定到一个 40 位提交号，所以更新是在市场里选新版本重装，或者插件页用新的固定提交 spec 更新。用分支名或标签装上的副本无法更新——DSH 要求 Git 依赖固定到完整提交才能替换。

## 我改了预设想生效

改 `packages/preset-smart-dev/cordis.patch.yml` 后重启 DSH。如果你是在 profile 的 `cordis.patch.yml` 里写的覆盖层，profile 层在 bundle 层之后应用，会盖住包内声明；但不要在 profile 里再声明一个同 id 的预设。
